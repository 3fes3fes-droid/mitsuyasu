# 動作・性能監査（v8）

## 結論

重さの主因だった全詳細データの初期一括読込と、検索・選択時の一覧全再生成は旧v2で撤去済みです。v8でも各話・人物等の詳細は選択中のチャンクだけを読み込みます。公式画像も一覧で一括取得せず、現在選択中の1件だけを外部取得します。

## 現行構成

- 一覧用カタログと選択中の詳細チャンクだけを読込
- 詳細チャンク：54ファイル
- 検索時：既存行の表示・非表示だけを切替
- 選択時：選択行と詳細欄だけを更新
- 人物・技／術式・用語のランダム化：元配列を変更しない一度の並べ替え
- 公式画像：選択中の1件のみ `loading="lazy"` で読込
- PC：左一覧＋右詳細の固定高2ペイン
- PC：一覧と詳細本文だけを領域内スクロール
- 詳細：概要・関連・出典等をタブで一つずつ表示
- 照合済み短文：表示中の話だけを読み、先頭6件以外は閉じた `details` 内へ配置
- 記事URL：短文ごとの重複を除き、ブラウザ用詳細チャンクでは話単位の一意なURL一覧へ縮約
- 狭い画面：固定高を解除し、一覧＋詳細の縦並びへ変形

## 現行ファイルサイズ

- `data/generated/catalog.js`：339,906 bytes
- `data/generated/catalog-volumes.js`：69,475 bytes
- 最大詳細チャンク：101,204 bytes
- コミックス表紙登録：31件
- 人物公式画像登録：180件
- 各話公式サムネイル登録：1件

画像URLはカタログに全画像を直接並べず、一覧側には有無と確認状態だけを保持します。実URLは選択中の詳細データまたはコミックス専用データから参照します。
